InferenceRail은 Triton 앞단에서 동작하는 ML inference gateway입니다. 같은 workload를 실제 serving 코드 경로에 replay해 p95·성공률 SLO를 지키는 정책을 고르고, 어디까지 안전한지 concurrency를 sweep한 뒤 Deployment Contract를 발행합니다.

왜 필요한가? batch size·queue·timeout을 감으로 정하면 평상시에는 멀쩡해 보여도 flash crowd에서 숨은 queue와 tail latency가 폭발합니다. InferenceRail은 선택 자체를 실행 증거로 남깁니다.

02 / WHY

남들과 다른 지점은 “서빙”이 아니라 “선택을 검증하는 방식”입니다.

Triton/Kubernetes를 썼다는 사실 자체는 차별점이 아닙니다. 이 프로젝트는 배포 전에 어떤 serving policy가 목표 SLO와 compute pressure를 동시에 만족하는지 재현 가능한 증거로 결정합니다.

1 / COUNTERFACTUAL같은 workload를 세 정책에 replay

Latency / Throughput / Availability 정책을 동일 조건의 실제 코드 경로에서 비교합니다.

2 / SAFE ENVELOPEconcurrency를 실제로 올려 경계를 찾음

마지막 SLO 통과 지점과 첫 실패 지점을 측정해 “어디까지 버티는지”를 숫자로 남깁니다.

3 / CONTRACT결론을 복사 가능한 config로 발행

batch·queue·timeout·breaker 설정과 scale/shed 경계를 한 Decision Receipt에 묶습니다.
