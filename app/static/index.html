01 / WEAPON

SLO Governor — 감으로 튜닝하지 않습니다.

하나의 synthetic workload를 격리된 실제 DynamicBatcher + CircuitBreaker 경로에 동일하게 replay합니다. SLO를 만족한 후보 중 모델 호출 수가 가장 적은 정책을 선택하고, 탈락한 정책의 이유까지 receipt로 남깁니다.

02 / LOGIC

같은 트래픽, 다른 선택. 결과로 결정합니다.

비용을 임의의 달러로 환산하지 않습니다. batching이 실제 backend 호출을 얼마나 줄였는지를 compute pressure proxy로 사용합니다.

STEP 1Workload fingerprint

동일 요청 수·동시성·장애 스케줄을 고정해 비교 조건이 바뀌지 않도록 합니다.

STEP 2Counterfactual replay

Latency / Throughput / Availability 세 정책을 실제 batcher와 breaker 코드 경로에서 각각 실행합니다.

STEP 3Decision receipt

SLO 통과 후보 중 backend calls / 100 success가 가장 낮은 정책을 고르고 탈락 이유를 남깁니다.

03 / EVIDENCE

깊게 보고 싶은 개발자를 위한 증거.
